Key business & visibility rules (§5.6, §6.7, §6.8)

  • category drives type: on every create/update, the server derives type from category: assaig -> assaig; {actuacio, taller, diada, trobada} -> actuacio; {reunio, termini, altre} -> altre.
  • Non-publishable categories: if category ∈ {reunio, termini}, server always forces published = false.
  • Dates & Madrid DST (§5.1, §10.1.7): endDate >= date (422 must_be_after_date if violated). allDay = true events store the UTC instant corresponding to midnight 00:00 in Europe/Madrid on that day. Query filters from=YYYY-MM-DD and to=YYYY-MM-DD are inclusive calendar days in Europe/Madrid ([from 00:00 Madrid, (to + 1 day) 00:00 Madrid)), handling March/October DST transitions accurately.
  • Audience mapping:
  • public (/public/events, /public/events/{id}, /public/events.ics): only published = true (404 otherwise); strictly public fields of §5.6; Cache-Control: public, max-age=300.
  • member: sees public + members fields (meetingTime, meetingPoint, dressCode, ownerId, attendanceOpen, attendanceSummary); does not see published or notes (staff), nor contractId/documentIds (board).
  • technical: adds published and notes; does not see contractId/documentIds.
  • board/admin: full event including derived contractId and documentIds.
  • Gallery limit: max 50 images per event (422 if exceeded); POST /api/v1/events/{id}/gallery accepts multiple file parts in one multipart call.
  • Deletion with linked documents: documents.event_id has ON DELETE RESTRICT; DELETE /api/v1/events/{id} returns 409 in_use if documents are attached (otherwise deletes event, cascades gallery/figures/groups/attendance, and cleans stored image files from FILES_DIR).
  • iCalendar (RFC 5545): GET /api/v1/public/events.ics exports published = true events in [now - 2 months, now + 12 months] with Content-Type: text/calendar; charset=utf-8, stable UID: event-{id}@muixerangadelx.com, DTSTART/DTEND (for allDay: VALUE=DATE with exclusive DTEND = date + 1 day; for timed events: UTC YYYYMMDDTHHMMSSZ), SUMMARY, DESCRIPTION, LOCATION, STATUS (CANCELLED / CONFIRMED / TENTATIVE). Private GET /api/v1/events/export?from=&to=&format=json|ics uses members visibility.

Sections

Europe/Madrid date range & DST handling (§10.1.7)

Contents

Convert from=YYYY-MM-DD to LocalDate.atStartOfDay(ZoneId.of("Europe/Madrid")).toInstant() and to=YYYY-MM-DD to LocalDate.plusDays(1).atStartOfDay(ZoneId.of("Europe/Madrid")).toInstant() (exclusive upper bound).

Behavior

Events overlapping [fromInstant, toExclusiveInstant) match, guaranteeing 23-hour spring-forward and 25-hour fall-back days behave accurately.

RFC 5545 iCalendar output

Contents

Include BEGIN:VCALENDAR, VERSION:2.0, PRODID:-//Muixeranga d'Elx//Tabala//CA, CALSCALE:GREGORIAN, X-WR-CALNAME:Muixeranga d'Elx, X-WR-TIMEZONE:Europe/Madrid, and one VEVENT per event.

Behavior

Escape commas/semicolons/newlines per RFC 5545 and fold lines > 75 octets with CRLF + space. For allDay events emit DTSTART;VALUE=DATE:YYYYMMDD and DTEND;VALUE=DATE:<nextDay>; for timed events emit UTC timestamps (DTEND defaults to DTSTART + 2h if endDate == null).
