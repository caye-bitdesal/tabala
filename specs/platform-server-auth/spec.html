Overview

Third platform slice after infra, schema v0.2, and :core contract. Wires Ktor Authentication + routes under /api/v1/auth/* and /api/v1/me* using SQLite v0.2 tables (platform-schema-v02) and :core DTOs (platform-core-contract).

Source of truth: docs/especificacion-tecnica.md v1.3 §4.1–4.5, §5.4, §6.6–6.7, §6.10 · docs/decisiones.md (Google OIDC, no Firebase).

Prerequisites

  • platform-server-infra: EnvConfig, DatabaseAccess, Koin, CORS+credentials, TrustedProxy, RequestUserIdKey, ErrorHandling.
  • platform-schema-v02: google_identities, sessions, refresh_tokens, user_accounts, users, user_guardians.
  • platform-core-contract: auth + UserSelf/UserPatchMe/MeResponse DTOs, PatchField, permissionsForRole.

Acceptance (slice)

  • ./gradlew :server:test green including full auth integration tests with a local test RSA JWKS server (GOOGLE_JWKS_URL).
  • POST /api/v1/auth/google (native) → 200 + accessToken + refreshToken; POST /api/v1/auth/refresh rotates refresh token; reusing a previously used refresh token → 401 and revokes the entire session.
  • POST /api/v1/auth/google (web) sets Set-Cookie: mux_refresh (HttpOnly; SameSite=Strict; Path=/api/v1/auth; Secure enabled when PUBLIC_BASE_URL starts with https://, omitted on local http://; Domain set only when COOKIE_DOMAIN is non-blank).
  • POST /api/v1/auth/logout accepts either Bearer or mux_refresh cookie (idempotent) so an expired JWT still revokes the session and clears the cookie.
  • GET /api/v1/me returns UserSelf (including emergencyContact, isMinor, notes, and guardians when minor) + permissions list.
  • PATCH /api/v1/me requires version (409 version_conflict on mismatch), ignores unknown fields (§6.4), rejects known non-editable User fields with 403 field_not_editable, and persists allowed §5.4 fields.
  • When consent.dataProcessing == false, any non-allowlisted authenticated route returns 403 consent_required; allowlist includes /me, PATCH /me, /me/export, /me/sessions*, /auth/logout, /auth/logout-all.
  • BOOTSTRAP_ADMIN_EMAIL creates one invited admin user on empty DB (idempotent).
  • No Google ID token, googleSub, or raw refresh token ever appears in responses (except native refreshToken) or logs.

Structure

Authentication request lifecycle:

POST /api/v1/auth/google
  → Origin CSRF check (if Origin present, must be ∈ CORS_ORIGINS)
  → Auth rate limit (20 / 15 min per resolved client IP)
  → GoogleIdTokenService.verify(idToken, nonce)
  → AccountLinkingService.linkOrResolve(sub, email) [write tx]
  → SessionService.createSession(userId, clientType, userAgent) [write tx]
  → JwtService.issue(userId, role, sid)
  → Response: AuthTokenResponse + Set-Cookie mux_refresh (web) | refreshToken (native)

Protected request (Authorization: Bearer <jwt>)
  → JwtService.verify → AuthPrincipal(userId, role, sid)
  → SessionService.assertActive(sid, userId) [≤30s cache + immediate local invalidation]
  → call.attributes.put(RequestUserIdKey, userId)
  → ConsentRequiredPlugin (unless route is allowlisted)
  → Route handler

Sections

Cookie policy (production vs local development)

Contents

Cookie name: mux_refresh, HttpOnly, SameSite=Strict, Path=/api/v1/auth, Max-Age=2592000 (30 days).

Behavior

Set Secure when PUBLIC_BASE_URL starts with https://; omit Secure on local http:// dev so browsers store the cookie. Set Domain=<COOKIE_DOMAIN> only when COOKIE_DOMAIN is configured (omit in local dev → host-only cookie on localhost). On logout, expire cookie with matching attributes (Max-Age=0).

PATCH /me field classification (§5.4 & §6.4)

Contents

Editable self fields: nickname, phoneNumber, aboutMe, address, emergencyContact, sizes, consent.dataProcessing (monotonic false -> true), consent.publicProfile, consent.imageRights, consent.whatsapp, consent.signedAt, consent.signedBy, plus required version.

Behavior

Inspect incoming raw JsonObject before decoding UserPatchMe: unknown JSON keys are ignored (§6.4); known non-editable User keys (name, lastNames, birthDate, documentId, email, status, membershipType, memberNumber, joinedAt, leftAt, heightCm, guardians, account, notes, groupId) return 403 field_not_editable. Version mismatch returns 409 version_conflict with error.current.

consent_required allowlist (`decisiones.md`)

Contents

While consent.dataProcessing == false, the user can access only: GET /api/v1/me, PATCH /api/v1/me, GET /api/v1/me/export, GET /api/v1/me/sessions, DELETE /api/v1/me/sessions/{id}, POST /api/v1/auth/logout, POST /api/v1/auth/logout-all.

Behavior

Every other authenticated /api/v1/* route returns 403 consent_required. Tests verify this by registering a test-only probe route inside testApplication (never shipped in production routing).

Logout without active Bearer token

Contents

POST /api/v1/auth/logout (§6.6) is callable even if the 15-minute access token has already expired.

Behavior

Verify Origin header if present. If a valid Bearer token is present, revoke its sid; else if mux_refresh cookie (or body refreshToken) matches a session, revoke that session; always clear mux_refresh cookie and respond 204.

Persistence

SQLite v0.2 via SQLDelight (Auth.sq) and DatabaseAccess.writeTransaction. Refresh tokens are 32 cryptographically random bytes encoded base64url; only SHA-256 hex/base64 hash is persisted.
