Overview

Fase 3 slice enabling members to RSVP to open rehearsals/performances and enabling technical/board staff to take attendance after the event.

Source of truth: docs/especificacion-tecnica.md v1.3 §4.4, §5.12, §6.7 (asistencia), §7.4 (Calendari detail integration) · docs/decisiones.md.

Prerequisites

  • platform-schema-v02 (attendance with UNIQUE(event_id, user_id) and comment ≤ 200 chars).
  • platform-core-contract (Attendance, AttendanceStatus, AttendanceSummary).
  • platform-server-auth, spec-03-calendar (EventDetailScreen attendance slot + Event.attendanceSummary), spec-05-members, platform-openapi-deploy.

Key business & visibility rules (§5.12 & §6.7)

  • Self RSVP (PUT /api/v1/events/{id}/attendance/me): allowed for any authenticated role (member+) with body {status, comment?}:
  • status MUST be one of yes, no, maybe (422 validation_failed if attended/absent).
  • Requires event.attendanceOpen == true (422 validation_failed otherwise).
  • Requires event has not started yet: for timed events now < event.date; for allDay events now < startOfNextDay(event.date in Europe/Madrid) (members can still RSVP on the day of an all-day event until end of day, or before event.date if timed — exact check documented in AttendanceService).
  • Server sets answeredAt = Clock.System.now() (read-only) and upserts (eventId, currentUserId).
  • Staff attendance roll-call (PUT /api/v1/events/{id}/attendance/{userId}): allowed for technical, board, admin (403 for member) with body {status, comment?}:
  • Validates userId exists and is not deleted (404/422).
  • Allows setting attended or absent (and correcting RSVP yes/no/maybe if needed by staff, e.g. member confirmed via WhatsApp).
  • Upserts (eventId, userId) preserving original answeredAt if already set or stamping now().
  • Listing (GET /api/v1/events/{id}/attendance):
  • member: returns a list containing only their own Attendance row (0 or 1 item, including their own comment) so members never see other members' comments (comment visibility is staff per §5.12).
  • technical, board, admin: returns all Attendance rows for the event with basic member summary (userId, name, lastNames, nickname, avatar) + comment.
  • Public API: none (attendance is strictly private).
  • Live Event.attendanceSummary: every RSVP or staff update is immediately reflected in Event.attendanceSummary ({yes, no, maybe, attended, absent}) queried by spec-03-calendar.

Sections

RSVP time window & validation rules

Contents

For PUT /events/{id}/attendance/me: verify event exists (404), event.attendanceOpen == true, status ∈ {yes, no, maybe}, comment.length <= 200, and current instant is before cutoff (event.date for timed events; startOfNextDay(event.date in Europe/Madrid) for allDay events).

Behavior

Return 422 validation_failed with clear Valencian message when closed, past start, or invalid status. Inject Clock into AttendanceService so tests verify before/after cutoff deterministically.

Visibility of `comment` and roster

Contents

member calling GET /events/{id}/attendance receives only their own record (if any), never other members' rows or comments.

Behavior

technical, board, and admin receive the full list of respondents plus staff roll-call controls to mark attended / absent for any active colla member (even if the member did not RSVP beforehand).
