Overview

Fase 3 protected document repository for board minutes, invoices, contracts, grants, statutes, insurance policies, and signed RGPD consent forms.

Source of truth: docs/especificacion-tecnica.md v1.3 §4.4, §5.11, §6.7 (documentos), §6.9 (ficheros protegidos), §7.4 (Documents) · docs/decisiones.md.

Prerequisites

  • platform-schema-v02 (documents, stored_files).
  • platform-core-contract (Document, DocumentKind, DocumentPatch, FileRef).
  • platform-server-auth, platform-files (FileStorageService.storeDocument, 50 MB PDF/image/Office magic-byte validation, protected download with Content-Disposition: attachment), platform-me-rgpd (BrowserFileDownload), platform-web-shell (SessionManager.fetchAuthorizedBytes), platform-openapi-deploy.

Key business & security rules (decisiones.md & §5.11)

  • Strictly board and admin only (anonymous → 401; member and technical → 403 on all /api/v1/documents* endpoints and on protected document file downloads). Never exposed on /public/*. (Note: a member can see metadata of their own userId = me documents inside GET /api/v1/me/export per decisiones.md.)
  • Multipart upload contract (POST /api/v1/documents, decisiones.md): uses multipart/form-data with individual form fields (simplest for Ktor Client across Web and future Android clients, plus curl -F): title (required, max 200), kind (required, DocumentKind snake_case), date (optional YYYY-MM-DD), eventId (optional), userId (optional), notes (optional) + file (required binary part, max 50 MB, allowed MIME by magic bytes: PDF, JPEG, PNG, WebP, DOCX, XLSX, ODT, ODS). Subject to the upload rate limit (30/min/user).
  • Update (PATCH /api/v1/documents/{id}): RFC 7386 JSON Merge Patch with required version updating metadata (title, kind, date, eventId, userId, notes). File replacement is done by uploading a new document or deleting/re-uploading (immutable file per document record keeps audit clarity).
  • Deletion (DELETE /api/v1/documents/{id}): removes the documents row and deletes the corresponding stored_files row + disk file in FILES_DIR post-commit (204).
  • Authenticated browser download (decisiones.md): because GET /api/v1/files/{id}/{filename} requires Authorization: Bearer for protected documents (never cookies), clicking «Descarrega» in the webapp fetches bytes via SessionManager.fetchAuthorizedBytes(doc.file.url) and triggers a browser download via BrowserFileDownload.downloadBytes(...).
  • Foreign key validation: when eventId or userId is provided, verify the referenced row exists (422 validation_failed if missing). Documents are preserved when a user is soft-deleted or anonymized (decisiones.md).

Sections

Multipart form fields (`POST /api/v1/documents`, `decisiones.md`)

Contents

Accept flat PartData.FormItem fields (title, kind, optional date, optional eventId, optional userId, optional notes) alongside a single PartData.FileItem named file.

Behavior

Read form fields and stream file to temp storage via FileStorageService.storeDocument (50 MB cap, magic-byte check). If any field validation fails (422), clean up the temp file immediately before returning ApiErrorResponse.

Listing filters & sorting

Contents

GET /api/v1/documents supports page, perPage, kind, eventId, userId, year (matches date year or createdAt year when date is null), q (search in title, notes), and sort (date, title, createdAt; default -date).

Behavior

Every returned Document embeds file: FileRef (pointing to /api/v1/files/{id}/{safeName} and optional thumbUrl when the document is an image).
