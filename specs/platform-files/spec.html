Key design rules (decisiones.md & §6.9)

  • Magic-byte sniffing (no extension trust): inspect file headers to allow strictly:
  • Images (max 10 MB; avatars max 5 MB): image/jpeg, image/png, image/webp.
  • Documents (max 50 MB): application/pdf, image/jpeg, image/png, image/webp, and Office OOXML/ODF (docx, xlsx, odt, ods — verified as ZIP magic bytes + expected internal entry such as word/document.xml, xl/workbook.xml, mimetype = ODF).
  • Any unsupported MIME → 415 unsupported_media_type; size exceeded → 413 file_too_large.
  • Memory-safe image processing (-Xmx256m): read image header dimensions *before* decoding pixels (via ImageReader.getWidth/getHeight); if width * height > 64_000_000 (64 MP) reject with 413 file_too_large without allocating the bitmap. Run decoding/resizing on Dispatchers.IO bounded by a Semaphore(permits = 2) so concurrent uploads never OOM. Resize longest edge to ≤2000 px and produce a ≤400 px thumbnail stored under thumb_storage_key.
  • WebP support: include TwelveMonkeys imageio-webp (or equivalent lightweight JVM ImageIO plugin) so WebP reads work reliably on JVM 21; re-encode processed images to JPEG/PNG/WebP cleanly.
  • Disk safety & cleanup: stream uploads to a temp file under FILES_DIR/.tmp while enforcing byte caps, generate random UUID storage keys (never original filename on disk), move atomically to FILES_DIR/<key>, and delete temp/old files on error, replacement, or entity deletion.
  • Thumbnails (decisiones.md): expose GET /api/v1/files/{id}/thumb/{filename} (referenced in FileRef.thumbUrl) applying the exact same access check as GET /api/v1/files/{id}/{filename}.
  • Owner-based visibility matrix: file visibility is derived dynamically from the owning entity's current state (e.g., an event image becomes public only while event.published == true; a user avatar becomes public only while user.status == active && consent.publicProfile == true && !isMinor; Document.file is always protected for board/admin with Content-Disposition: attachment).

Acceptance (slice)

  • ./gradlew :server:test passes.

Structure

Upload & download architecture:

Multipart upload (PUT /me/avatar or feature upload route)
  → Stream part to FILES_DIR/.tmp/<uuid> enforcing maxBytes (5 MB / 10 MB / 50 MB)
  → MagicByteSniffer validates real MIME (415 if unsupported)
  → If image: ImagePipeline checks header dimensions ≤ 64 MP (413), Semaphore(2), resize ≤2000 px + thumb ≤400 px
  → Atomic move to FILES_DIR/<storageKey> (+ <thumbStorageKey>)
  → DB writeTransaction: insert stored_files + update owner *_file_id + bump version
  → Post-commit: delete previous stored_files row & old disk files
  → Return FileRef(id, url, thumbUrl, contentType, size)

Download (GET /api/v1/files/{id}/{filename} or /thumb/{filename})
  → Load stored_files by id (404 if missing)
  → FileAccessPolicy checks owner entity state + optional Bearer principal (404 if denied)
  → Stream file from FILES_DIR with nosniff + Cache-Control + Content-Disposition

Sections

Owner visibility matrix (`FileAccessPolicy`)

Contents

Visibility is evaluated against the current DB state of the owning record (never solely a static flag, so unpublishing an event or revoking publicProfile immediately hides its files):

Behavior

  • user.avatar: public iff user.status == 'active' && consent_public_profile == 1 && !isMinor; otherwise private to self, staff, board, admin (plus any authenticated member if the user holds an active org_role shown in internal /org-chart).
  • event.image / event.gallery: public iff event.published == 1; otherwise any authenticated member+.
  • group.logo / group.image / achievement.logo: public.
  • figure.image: public iff figure.status != 'retired'; otherwise any authenticated member+.
  • inventory_item.image: private (board, admin only).
  • document.file: always protected (board, admin only), served with Content-Disposition: attachment; filename="<sanitized>".

Thumbnail route (`FileRef.thumbUrl`)

Contents

Every processed image stores both storage_key (≤2000 px) and thumb_storage_key (≤400 px). FileRef.url points to {PUBLIC_BASE_URL}/api/v1/files/{id}/{safeName} and FileRef.thumbUrl points to {PUBLIC_BASE_URL}/api/v1/files/{id}/thumb/{safeName}.

Behavior

For non-image documents (PDF, DOCX, XLSX, ODT, ODS), thumb_storage_key and FileRef.thumbUrl are null; requesting /thumb/ on a non-image returns 404.

Multipart limits & Netty event-loop safety

Contents

Upload routes bypass the 1 MB JSON body limit from platform-server-infra and enforce per-endpoint caps (5 MB avatar, 10 MB images, 50 MB documents; Caddy allows up to 60 MB).

Behavior

All disk I/O, ZIP entry inspection, and ImageIO resizing run strictly on Dispatchers.IO. On upload failure or DB rollback, delete newly written files in a finally block so FILES_DIR never leaks orphan blobs.
