Platform rate limiting (§6.10)

Unified in-memory rate-limiting plugin on :server covering all 5 scopes of §6.10 (/public/*, authenticated private routes, /auth/google, /auth/refresh, and file uploads) with bounded memory (-Xmx256m), trusted 127.0.0.1 X-Forwarded-For IP resolution, and 429 rate_limited + Retry-After. Server only.

Overview

Unifies and completes request throttling across the entire API so a single consistent mechanism protects auth, public routes, private routes, and heavy multipart uploads without external Redis.

Source of truth: docs/especificacion-tecnica.md v1.3 §6.3, §6.10, §8 (NFR-01 -Xmx256m).

Prerequisites

  • platform-server-infra (TrustedProxy.resolvedClientIp(), ErrorHandling ApiErrorResponse).
  • platform-server-auth (AuthPrincipal.userId + existing auth limits to unify under this plugin).

Scopes (§6.10)

  • public (/api/v1/public/* + anonymous /api/v1/files/*): 120 req / min per client IP.
  • private (authenticated /api/v1/* routes): 300 req / min per userId.
  • auth-google (POST /api/v1/auth/google): 20 req / 15 min per client IP.
  • auth-refresh (POST /api/v1/auth/refresh): 60 req / min per client IP.
  • upload (multipart file upload routes: avatars, event image/gallery, inventory/group/achievement/figure images, POST /documents): 30 req / min per userId.

Memory & testability rules

  • Bounded bucket map (max 10 000 entries per scope with periodic stale-entry eviction every 5 min) so IP-flood traffic cannot exhaust -Xmx256m heap.
  • Inject Clock / TimeSource and rateLimitingEnabled: Boolean in EnvConfig (default true; tests can toggle or inject a fake clock for deterministic assertions without delay()).
  • On limit exceeded: respond 429 Too Many Requests with Retry-After: <seconds> header and §6.3 JSON body {"error":{"code":"rate_limited","message":"Massa peticions. Torna-ho a provar en uns segons."}}.

Acceptance (slice)

  • ./gradlew :server:test passes.
  • Deterministic tests with fake clock verify exact thresholds for all 5 scopes, 429 rate_limited JSON body, Retry-After header, and window reset.
  • Spoofed X-Forwarded-For from a non-loopback peer does not bypass IP limits.
  • Auth routes reuse this unified plugin instead of duplicate ad-hoc counters.

Sections

Trusted client IP resolution

Contents

Always derive IP keys via TrustedProxy.resolvedClientIp() from platform-server-infra.

Behavior

When the direct TCP peer is 127.0.0.1 (Caddy), use the right-most untrusted X-Forwarded-For IP; otherwise ignore X-Forwarded-For completely and use the socket remote address.

Bounded memory & test isolation

Contents

Each scope caps active keys at 10 000 and evicts idle buckets periodically (every 5 minutes).

Behavior

Provide a test constructor / EnvConfig switch so unrelated integration tests are not affected by rate limits while dedicated RateLimitTest tests exercise every threshold deterministically with a fake clock.

Persistence

In-memory only (no SQLite writes for rate limiting).
