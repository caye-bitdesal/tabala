Migration policy (greenfield pre-production)

  • No production data yet → replace V1__initial_schema.sqm (0.1) with the v0.2 baseline DDL plus V2__seed.sqm.
  • Once deployed to production, never edit applied migrations — add V3__… onwards.
  • Developers with an old local DB delete DB_PATH before starting the server (noted in Database.kt KDoc).
  • Pipeline: edit .sqm → ./gradlew :server:generateMainTabalaDatabaseMigrations → Flyway applies generated db/migration/*.sql at runtime.

Key v0.2 + decisiones.md schema rules

  • users.status CHECK: ('active', 'inactive', 'on_leave', 'deleted') (deleted replaces former). height_cm CHECK (height_cm BETWEEN 50 AND 250). Add preferred_locale TEXT NOT NULL DEFAULT 'ca' CHECK (preferred_locale IN ('ca', 'es')). Drop board_role, board_role_since. Add version.
  • areas: add kind ('board', 'area') with unique partial index WHERE kind = 'board'; make slug NOT NULL UNIQUE; keep optional meeting_frequency IN ('weekly', 'biweekly', 'monthly', 'as_needed'); drop goals; add version.
  • inventory_items: add supplier reorder & sales columns (supplier_contact TEXT, supplier_reference TEXT, min_order_qty INTEGER CHECK (min_order_qty >= 0), lead_time TEXT, last_ordered_at TEXT, units_sold INTEGER NOT NULL DEFAULT 0 CHECK (units_sold >= 0), revenue_cents INTEGER NOT NULL DEFAULT 0 CHECK (revenue_cents >= 0)) and version.
  • Organigrama: add org_roles (area_id REFERENCES areas(id) ON DELETE RESTRICT, UNIQUE(area_id, name), version) and org_role_holders (PRIMARY KEY(org_role_id, user_id), FK ON DELETE CASCADE); drop area_members.
  • Auth (§4.5): user_accounts drops auth_provider and auth_uid (no Firebase); add google_identities, sessions, refresh_tokens. Invariant (status != 'invited' => google_identities row exists) enforced in AccountLinkingService transaction.
  • events: category NOT NULL, status NOT NULL DEFAULT 'planned', version.
  • figures & positions: figures.name UNIQUE, positions adds UNIQUE (figure_id, x, y, z) and CHECK (x BETWEEN -20 AND 20 AND y BETWEEN -20 AND 20 AND z BETWEEN 0 AND 8).
  • stored_files (§6.9): stores metadata + internal storage_key (random filename on disk) + optional thumb_storage_key (400 px thumbnail); domain media columns become *_file_id REFERENCES stored_files(id) ON DELETE SET NULL (and documents.file_id NOT NULL REFERENCES stored_files(id) ON DELETE RESTRICT, event_gallery.file_id NOT NULL REFERENCES stored_files(id) ON DELETE RESTRICT).
  • version INTEGER NOT NULL DEFAULT 1 on all mutable entity tables updated via PATCH/PUT: groups, users, areas, org_roles, events, contracts, inventory_items, achievements, figures, position_types, documents.

Sections

stored_files table and media foreign keys (§6.9)

Contents

stored_files: id TEXT PK, owner_type TEXT NOT NULL, owner_id TEXT NOT NULL, field TEXT NOT NULL, original_name TEXT NOT NULL, storage_key TEXT NOT NULL UNIQUE, thumb_storage_key TEXT, content_type TEXT NOT NULL, size INTEGER NOT NULL CHECK (size >= 0), protected INTEGER NOT NULL DEFAULT 1 CHECK (protected IN (0, 1)), created_at TEXT NOT NULL.

Behavior

Media references across tables become *_file_id REFERENCES stored_files(id): users.avatar_file_id, groups.image_file_id, groups.logo_file_id, events.image_file_id, event_gallery.file_id, inventory_items.image_file_id, achievements.logo_file_id, figures.image_file_id, documents.file_id. Index stored_files(owner_type, owner_id) for cleanup.

Optimistic locking (`version`) and child tables

Contents

Add version INTEGER NOT NULL DEFAULT 1 CHECK (version >= 1) to every aggregate root updated via PATCH/PUT: groups, users, areas, org_roles, events, contracts, inventory_items, achievements, figures, position_types, documents.

Behavior

Child/join tables (user_guardians, org_role_holders, event_gallery, event_figures, event_groups, inventory_variants, positions) inherit versioning from their parent aggregate (for example PUT /figures/{id}/positions checks and increments figures.version). attendance is upserted per (event_id, user_id) and does not require client version.

Seed data (§12.1 and §12.2)

Contents

Insert 8 areas (slugs: junta, tecnica, xicalla, membres, marqueting, esdeveniments, relacions, material), 40 org_roles with exact is_lead flags and descriptions for Legal extern and Legal intern, 1 own groups row («Muixeranga d'Elx», «Fem pinya com una tabala», foundation = 2022, is_own = 1), and 10 position_types with ASCII slugs (mestre, bases, alcadors, contrafort, escala, mans, passador, segon, terc, xicalla) and Valencian name labels.

Behavior

Use fixed deterministic UUIDs in V2__seed.sqm for areas, org_roles, and own group so tests and references remain reproducible across environments. Never insert users or org_role_holders in migrations.

Constraints updated from v0.1

Contents

Fix v0.1 gaps discovered against §5: users.status IN ('active','inactive','on_leave','deleted'), users.height_cm BETWEEN 50 AND 250, areas.slug NOT NULL UNIQUE, areas.kind IN ('board','area') with unique partial index for kind = 'board', events.category NOT NULL, events.status NOT NULL DEFAULT 'planned', figures.name NOT NULL UNIQUE, positions UNIQUE (figure_id, x, y, z) and CHECK (x BETWEEN -20 AND 20 AND y BETWEEN -20 AND 20 AND z BETWEEN 0 AND 8).

Behavior

Keep documents.event_id REFERENCES events(id) ON DELETE RESTRICT and documents.user_id REFERENCES users(id) ON DELETE RESTRICT so historical documents are never silently lost; DELETE /users/{id} and anonymize never physically delete the users row (only admin ?hard=true fails with 409 in_use if documents exist).

Persistence

SQLite on :server only. Two Flyway migrations (V1 DDL + V2 seed) generated from .sqm. WAL, foreign_keys = ON, and busy_timeout = 5000 enforced via DatabaseAccess.
