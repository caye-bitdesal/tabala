Overview

First functional Fase 2 slice. Exposes the v0.2 organigrama seeded by platform-schema-v02 (V2__seed.sqm) through private and public APIs and renders the interactive hierarchy in the management webapp.

Key business & RGPD rules

  • Only one Area can have kind = board (enforced by partial unique index → 409 duplicate). Area.slug is unique globally; (OrgRole.areaId, OrgRole.name) is unique per area (409 duplicate).
  • Deleting an Area that still has org_roles fails with 409 in_use (ON DELETE RESTRICT). Deleting the board area is forbidden (409 in_use / 422).
  • PUT /api/v1/org-roles/{id}/holders validates version (409 version_conflict), verifies every holderId refers to an existing non-deleted user (422 validation_failed otherwise), deduplicates IDs, replaces org_role_holders in one transaction, and increments org_roles.version.
  • Private GET /api/v1/org-chart returns Junta first (kind = board), then areas ordered by sort_order, name, with each area's roles ordered by sort_order, name and holder summaries {id, name, lastNames, nickname, avatar} (includes minors internally per decisiones.md). notes on Area is included only for board/admin (null/omitted for member/technical).
  • Public GET /api/v1/public/org-chart (Cache-Control: public, max-age=300): returns all areas (id, name, slug, kind, order) and roles (id, areaId, name, isLead, order, holders) where holders includes only users with status = active && consent.publicProfile == true && !isMinor. Never exposes vacant boolean or hidden holder counts (so callers cannot infer whether a role is held by a minor or non-public member).

Sections

Public RGPD filtering (§5.5 & §6.8)

Contents

GET /api/v1/public/org-chart exposes the full organizational structure (Junta + areas ordered by order, all roles ordered by order with name and isLead), but filters holders strictly to active adult members with consent.publicProfile == true.

Behavior

Never include vacant, notes, whatsappGroup, description, or any count of omitted holders on the public response. Compute isMinor in Europe/Madrid timezone from birth_date.

UI hierarchy, filtering & board drawers (§7.4 & mockups)

Contents

Top KPI strip shows 4 cards inside the light-grey container: Àrees, Càrrecs, Vacants (cream fill, red count), and Persones amb càrrec. Filter toolbar provides Filtra per persona and a Només vacants toggle switch.

Behavior

Selecting/filtering a person highlights every role they hold, dims other rows, and displays a summary strip («<Nom> ocupa: <càrrec 1>; <càrrec 2>»). Toggling Només vacants filters each area card to display only vacant role rows. Users with board/admin see + EDITA L'ORGANIGRAMA (opening the Gestiona les àrees right-side drawer to add/reorder/change status/delete areas), per-area EDITA buttons (opening Edita l'àrea right-side drawer with Nom, Descripció, Estat, Color, Grup de WhatsApp, Freqüència de reunió, and yellow-accented Notes internes), and role-click editing to update role details and assign holders (PUT /org-roles/{id}/holders).
