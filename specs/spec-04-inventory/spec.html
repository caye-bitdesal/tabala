Key business rules (§5.8, §6.7 & decisiones.md)

  • Strictly board and admin only (anonymous → 401; member and technical → 403; never public).
  • Variants: every item MUST have ≥ 1 variant with unique label (case-insensitive trimmed uniqueness within item; default single variant label = "única"), quantity >= 0, minStock >= 0. Derived fields: totalQuantity = sum(variants.quantity) and lowStock = variants.any { it.quantity <= it.minStock }.
  • Supplier reorder fields (decisiones.md): optional supplier, supplierContact, supplierReference, minOrderQty (>= 0), leadTime, lastOrderedAt (LocalDate), and unitCost (MoneyCents), shown in the «Informació de comanda» modal and editable in «Edita l'article».
  • Atomic stock adjustment (POST /api/v1/inventory-items/{id}/adjust): body {"variant": "M", "delta": -1} (no version required). Executed atomically in SQL (UPDATE inventory_variants SET quantity = quantity + :delta WHERE item_id = :id AND label = :label AND quantity + :delta >= 0): rejects archived items (422), unknown variant label (404/422), and any result < 0 (422 validation_failed).
  • Atomic sale registration (POST /api/v1/inventory-items/{id}/sell, decisiones.md): body {"variant": "S", "quantity": 1, "unitPrice"?: 15.00} (quantity >= 1, default 1; no version required). Rejects archived items or items with forSale == false (422). Uses unitPrice if provided else item.salePrice (422 if null). In one write transaction: atomically decrements inventory_variants.quantity (guarded by quantity >= :qty, else 422), increments inventory_items.units_sold += :qty and revenue_cents += :qty * unitPriceCents, bumps updated_at, and returns the updated InventoryItem.
  • Summary formulas (GET /api/v1/inventory-items/summary, non-archived items only):
  • itemCount: count of non-archived items.
  • merchUnits: sum of quantity across variants of items with category = merch.
  • merchSaleValue: sum of variant.quantity * (item.salePrice ?: 0) (MoneyCents) across items with category = merch.
  • lowStockCount: count of non-archived items where lowStock == true.
  • uncountedCount: count of non-archived items where lastCountedAt == null («per comptar»).
  • Archiving: DELETE /api/v1/inventory-items/{id} sets archived = true (204); ?hard=true is admin only (also deletes stored item image from FILES_DIR).
  • Protected images: item photos are private (board/admin only); the web UI fetches thumbnails via SessionManager.fetchAuthorizedBytes(thumbUrl).

Sections

Filters, sorting & variant integrity

Contents

GET /api/v1/inventory-items supports page, perPage, category, lowStock (bool), forSale (bool), archived (default false), q (search in name, description, supplier, storageLocation), and sort (name, updatedAt, salePrice; default name).

Behavior

Creating/updating an item validates at least 1 variant, trims variant labels, checks uniqueness (422 validation_failed on duplicates), and ensures quantity >= 0, minStock >= 0, and non-negative MoneyCents prices.

Atomic adjust, sales registration & concurrency

Contents

Clicking REGISTRA VENDA opens the centered Registra venda modal showing item unit price, Talla o variant dropdown (showing current stock per variant), and a live preview box Existències després de la venda. Confirming sends POST /api/v1/inventory-items/{id}/sell and updates both the row (Quantitats per talla, Unitats venudes, Ingressos generats) and the KPI strip immediately. Direct stock edits or quick adjustments use POST /adjust.

Behavior

Server executes both /adjust and /sell inside DatabaseAccess.writeTransaction with guarded SQL UPDATE (quantity >= :qty / quantity + delta >= 0), so concurrent requests never produce negative stock and /sell atomically updates units_sold and revenue_cents.
