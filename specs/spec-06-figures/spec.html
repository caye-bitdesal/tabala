Overview

Fase 3 repertoire slice covering muixeranga figures, their 3D position placements (x, y, z), editable position types, public repertoire endpoints, and the interactive grid editor.

Source of truth: docs/especificacion-tecnica.md v1.3 §4.4, §5.10, §6.1.1, §6.7 (figuras), §6.8 (/public/figures*, /public/position-types), §7.4 (Figures), §12.2 · docs/decisiones.md.

Prerequisites

  • platform-schema-v02 (figures with name UNIQUE, positions with UNIQUE(figure_id, x, y, z), UNIQUE(figure_id, user_id), and CHECK(x BETWEEN -20 AND 20 AND y BETWEEN -20 AND 20 AND z BETWEEN 0 AND 8), position_types with 10 seeded types).
  • platform-core-contract (Figure*, Position*, PutFigurePositionsRequest(version, positions), PositionType*, FigureValidator).
  • platform-server-auth, platform-files (figure image upload), spec-05-members (member lookup for position assignment), platform-web-shell, platform-openapi-deploy.

Key business, permission & RGPD rules (decisiones.md & §5.10)

  • Split write permissions (§4.4 / §6.1.1):
  • figures and positions: read by member+ (and public); write (POST/PATCH/DELETE /figures*, PUT /figures/{id}/positions, image) by technical, board, admin.
  • position-types: read by member+ (and public); write (POST/PATCH/DELETE /position-types*) by technical and admin ONLY (board receives 403!). Deleting a PositionType still referenced by any Position returns 409 in_use (ON DELETE RESTRICT).
  • Transactional PUT /api/v1/figures/{id}/positions (decisiones.md): body PutFigurePositionsRequest(version: Int, positions: List<PositionInput>). Checks figures.version == request.version (409 version_conflict with current figure + positions if stale), validates all positions in one pass (x,y ∈ -20..20, z ∈ 0..8, no duplicate (x,y,z) → 409 duplicate / 422, no duplicate non-null userId in the same figure → 409 duplicate / 422, every positionTypeId exists, every non-null userId exists and is not deleted), atomically replaces all positions for figureId (preserving client-supplied id if already owned by the figure or generating UUIDv7), and increments figures.version.
  • Public API filtering (§5.10, §6.8):
  • GET /api/v1/public/figures and /public/figures/{id} (Cache-Control: public, max-age=300): exclude status = retired (404 on /public/figures/{id} if retired), omit videoUrl (visibility members), and map Position.userId = null whenever the assigned person is a minor, non-active, or has consent.publicProfile == false.
  • GET /api/v1/public/position-types: returns all position types with Cache-Control: public, max-age=300.

Sections

Transactional positions replace & optimistic locking (`decisiones.md`)

Contents

PUT /api/v1/figures/{id}/positions receives {version, positions: [{id?, positionTypeId, userId?, x, y, z}]}.

Behavior

Inside DatabaseAccess.writeTransaction: check figures.version == request.version (409 version_conflict with current figure if mismatch); validate every position (x,y ∈ -20..20, z ∈ 0..8, unique (x,y,z), unique non-null userId, existing positionTypeId and active/non-deleted userId); delete old rows and insert new set; increment figures.version; return updated positions + new version.

Visual grid editor UX (§7.4)

Contents

Editor displays level tabs Piso z (0 = Pinya/terra, 1..levels), a zoomable/pannable grid centered on (0,0) with coordinates x,y ∈ -20..20, and a side/bottom inspector.

Behavior

Supports both drag-and-drop and click/tap-to-place so it stays usable on mobile touch screens (≥360 px). Selecting a member who is already assigned to another cell in the same figure displays a clear Valencian warning and offers to move them from the previous cell.
